## Session 3 — The typography sweep · ~20 min · -0 lines, big legibility win

**This is the single highest-value systemization in the UI and it is a pure
find-and-replace.**

Tailwind v4 treats `--text-*` in `@theme` as the **font-size namespace**. Your
`styles.css` already defines the scale there, so the short utilities already
exist. Verified against your own `tailwindcss@4.3.3` and your own `@theme`:

```css
/* compiled from class "text-micro" */
.text-micro { font-size: var(--text-micro); }
```

Identical output to `text-[length:var(--text-micro)]`. You are writing the
31-character arbitrary form **176 times** and the short form **zero** times.

| Replace | With | Count |
|---|---|---|
| `text-[length:var(--text-micro)]` | `text-micro` | 84 |
| `text-[length:var(--text-meta)]` | `text-meta` | 64 |
| `text-[length:var(--text-body)]` | `text-body` | 10 |
| `text-[length:var(--text-headline)]` | `text-headline` | 7 |
| `text-[length:var(--text-display)]` | `text-display` | 6 |
| `text-[length:var(--text-section)]` | `text-section` | 5 |

```bash
grep -rl 'text-\[length:var(--text-' src | xargs sed -i '' -E 's/text-\[length:var\(--text-([a-z]+)\)\]/text-\1/g'
```

Same trick applies to `rounded-[var(--radius-sm)]` → `rounded-sm` and
`duration-[var(--duration-fast)]` → `duration-fast`. **Verify those two by
building before committing** — `--radius-*` and `--duration-*` are also Tailwind
v4 theme namespaces, but I only empirically confirmed `--text-*`.

After this sweep the repeated class clusters below become short enough to read,
which is what makes Session 4 obvious rather than speculative.

## Session 4 — Componentize: the three duplicated item renderers · ~2 hrs · -150 lines · DONE (2026-09-01)

**The real structural finding in the UI.** You already have the right
abstraction — `kind(item)` in `src/ui/archive/itemKind.tsx` returns
`{ label, render }` and is a clean dispatch table. But *three* components
independently reimplement "render an item at some size", and only some of them
use it:

| Component | Uses `kind()`? | Handles |
|---|---|---|
| `Preview` — `Archive.tsx:89` (60 lines) | yes | image, pdf, text, artifact, office, tweet, link, note |
| `ItemThumb` — `Taste.tsx:28` (16 lines) | yes | image, tweet, office/pdf, text |
| `Thumb` — `ConnectionsPanel.tsx:26` (6 lines) | **no** — raw `item.type` check | image, everything-else-is-a-file-icon |

`Thumb` bypassing `kind()` is the bug-shaped part: a captured tweet or a PDF
renders as a generic file glyph in the connections panel but correctly
everywhere else.

**Target:** one `<ItemPreview item size="tile" | "thumb" | "chip" />` in
`src/ui/archive/ItemPreview.tsx`. One `switch (kind(item).render)`, size only
changes classes and which fallbacks are worth rendering (no iframes at
thumb size). Delete all three call sites.

Do this *after* Session 3 — the class strings shrink by half and the shared
shape becomes visible.

**Landed as `src/ui/archive/ItemPreview.tsx`** — `size: "tile" | "thumb" | "chip"`,
one `kind()`-driven dispatch per size. `ConnectionsPanel`'s `Thumb` is gone;
its 24-32px containers now go through `ChipPreview`, which fixes the
described bug (a linked tweet/PDF/office doc now renders a type-matched glyph
instead of always the generic file icon). Net line count landed close to flat
(-142 across the three call sites, +151 for the new file) rather than the
planned -150 — the value here is one dispatch table and a real bug fix, not
raw deletion; three near-duplicate `if (render === ...)` chains collapsed
into one, each still needs its own JSX per size.

**Session 4b — DONE (2026-09-01).** `CapturePreview.tsx`'s `PreviewPane` and
the inline "Material" block in `ItemLightbox.tsx` shared 6 near-verbatim
branches (image/pdf/text/artifact/office/tweet) but diverged on the other
2-3: an editable note `<textarea>` (ItemLightbox only), an `<a>`-wrapped
link-image fallback (each wraps/gates it differently), and the terminal
fallback (a host chip vs a clickable source link).

Landed as `detailPreview(item)` in `ItemPreview.tsx` — a **plain function**,
not a component, exporting just the 6 shared branches and returning `null`
for everything else. The reason it's a function and not a 4th `size` value:
a component's JSX return is always "something" (even a fallback), so a
caller can't express "render the shared part, or my own bespoke thing if it
declined" — `<ItemPreview size="detail" item={item} />` has no way to signal
"I rendered nothing, you take over." A plain function returning `ReactNode |
null` does: `detailPreview(item) ?? <MyOwnFallback />`. Each caller kept its
own note/link/fallback JSX exactly as it was, wired through that `??`.

One cosmetic unification, flagged rather than silently made: the tweet
embed's max-width differed (520px in CapturePreview, 550px in ItemLightbox,
clearly incidental tuning, not a deliberate size difference) — picked 550px
for both.

One thing deliberately **not** merged: `CapturePreview.tsx` keeps its own
private `host(url: string | null)` with a try/catch around `new URL()`.
`itemKind.tsx`'s canonical `host(item)` has no try/catch (matches
`ItemLightbox`'s own inline `new URL(...)` calls, which would throw on a
malformed but non-empty `source_url`). Swapping `CapturePreview` to the
canonical helper would remove real defensive coverage for a onetime-typed
free-text source URL — not a safe 1:1 swap, left as is.

## Session 6 — The async plumbing hook · ~1 hr · -80 lines

Two patterns are copy-pasted across the UI:

**A. The cancelled-fetch effect** — 5 identical copies:
`Tweet.tsx`, `Workbench.tsx`, `Archive.tsx`, `useSpace.ts`, `Stats.tsx`

```ts
let cancelled = false;
fetchThing()
  .then((d) => !cancelled && setData(d))
  .catch((e) => !cancelled && setError(e instanceof Error ? e.message : "..."));
return () => { cancelled = true; };
```

**B. The busy/error action guard** — 4 near-identical copies:
`Archive.tsx:528`, `ConnectionsPanel.tsx:70`, `Taste.tsx:147`, `MemorySync.tsx:28`

```ts
setBusy(true); setBanner(null);
try { await fn(); }
catch (err) { setBanner(err instanceof Error ? err.message : "That didn't work."); }
finally { setBusy(false); }
```

And `err instanceof Error ? err.message : "…"` appears **8 times**.

Two small hooks in `src/ui/hooks/`:

```ts
useAsync(fn, deps)            // → { data, error, loading, reload }   replaces A
useAction()                   // → { run, busy, error, clearError }   replaces B
```

Plus `errorMessage(err, fallback)` in `src/api/client.ts` next to `ApiError`.

Do this **after** Session 5, not before — writing the hook against the split-out
`useArchive` is much easier than against the 982-line file.

## Session 7 — Judgement calls (discuss, don't just do) · ~1 hr

These are real findings but each has a defensible "leave it".

- **`Icon.tsx` (68 lines)** maps 20 Lucide components to your own names and adds
  nothing else. `import { ArrowRight } from "lucide-react"` is the same call.
  *Counter:* 13 consumers, and the indirection is genuinely cheap. **Recommend:
  keep.** It's the one wrapper that earns itself.
- **`BrandMark`, `GrantIcon`, `MetaList`, `SidePanel`** sit in `primitives/`
  with **one consumer each** — extracted before a second caller existed.
  **Recommend:** move next to their consumer; `primitives/` should mean shared.
- **`tokens.ts` duplicates `styles.css` `@theme`** by hand. A real sync hazard
  (already drifted: `rise` exists in TS, nothing like it in CSS). But `motion`
  variants do need JS literals. **Recommend:** keep `duration`/`ease` (78 and 30
  uses, genuinely needed by motion), delete `color`/`font` (7 uses each, all
  replaceable with Tailwind classes).
- **`extract.ts` regex-scrapes HTML** — `parsePageHtml` + `decodeEntities` hand-roll
  meta/link/img extraction and entity decoding (~90 lines) when Workers ship
  `HTMLRewriter` for exactly this. Would drop to ~30 lines. *Counter:* it works
  and it's tested. **Recommend:** only if you touch extraction for another reason.
  Leave the SSRF guards (`isPrivateIpv4`/`isPrivateIpv6`) completely alone.
- **Two tokenizers for one job** — `words()`+`STOP` in `taste/derive.ts:26` and
  `contentWords()`+`WORD` in `retrieval.ts:296`, each feeding its own hand-rolled
  Jaccard (`statementOverlap`, `jaccard`). **Recommend:** one shared pair in
  `shared/`, but only alongside the taste fixes below — they touch the same lines.

## Not cleanup — correctness, tracked separately

Found during the same pass. **Out of scope for these sessions**, listed so they
don't get lost:

1. **Taste barely reaches ranking.** Measured with the real formula: best case is
   a `1.10x` multiplier, realistic case `1.01x`, against `authority_weight` which
   spans `1.0 → 0.14`. Nothing crosses `TASTE_APPLIED_MIN = 0.1`, so
   `applied_signal_ids` ships empty and `"taste lifted it"` never renders.
   Session 1.4 deletes the dead half; the *rescale* is a separate design call.
2. **`directionOf()` regex-parses direction out of English prose**
   (`taste/derive.ts:44`). 4 of 6 plausible negative statements misparse as
   `"toward"`, which flips `supports`/`contradicts` and moves confidence the
   wrong way. Root cause: direction is known at derive time and thrown away.
   Fix is a `direction` column, not a better regex.
3. **Transient outbox errors are terminal** (`memory-outbox.ts:80`): a thrown
   handler error goes straight to `markFailed` without consuming an attempt. One
   R2 blip permanently unsyncs an item. Note this when inlining in Session 1.3.
4. **No outbox coalescing** (`queries.ts:1894`): editing an item 10× queues 10
   upserts of the same `customId`. One `DELETE ... WHERE item_id=? AND
   op='upsert' AND status='pending'` before insert fixes it.
5. **Global focus suppression** — `styles.css` ends with
   `*:focus, *:focus-visible { outline: none !important }`. Deliberate, per the
   comment, but it means the app is not keyboard-navigable. Worth a real
   decision rather than inheriting it.
